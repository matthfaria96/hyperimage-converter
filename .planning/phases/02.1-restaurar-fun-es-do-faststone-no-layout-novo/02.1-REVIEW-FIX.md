### WR-01: In-place template output ignored the "Pular" and "Perguntar" overwrite policies

**Files modified:** `Sources/HyperImageCore/Batch/ConvertSettings.swift`, `Tests/HyperImageCoreTests/EncoderTests.swift`
**Commit:** e3b4c4a
**Applied fix:**
- `OutputPlanner` now avoids existing files on disk only when all three hold: template naming is on, output goes in place, and the policy is "Substituir" (`!askBeforeOverwrite && !skipExisting`).
- With "Pular" and "Perguntar", the planner keeps the plain name (`Image00001.jpg`), so `BatchConverter.run` can skip it or ask about it.
- New tests:
  - `inPlaceTemplateKeepsPlainNameWhenSkipping` covers skip.
  - `inPlaceTemplateKeepsPlainNameWhenAsking` covers ask.
  - Both use an `exists: { _ in true }` stub.
- The existing test `inPlaceTemplateSkipsUnrelatedFilesOnDisk` now sets the replace policy explicitly.
- SAFE-01 still holds: every input path stays reserved in `used`.

### IN-05: Cancel had no effect while outputs were being planned, and the status read "Processando 0 de 0"

**Files modified:** `Sources/HyperImageCore/Batch/ConvertSettings.swift`, `Sources/HyperImageCore/Batch/BatchConverter.swift`, `Sources/HyperImage/Convert/ConversionRunner.swift`, `Sources/HyperImage/Convert/SummaryBox.swift`, `Resources/Localizable.xcstrings`, `Tests/HyperImageCoreTests/EncoderTests.swift`
**Commit:** 8ab77a7
**Applied fix:**
- `OutputPlanner.destinations` has a new `isCancelled:` parameter that defaults to `{ false }`. It stops planning as soon as that returns true.
- New `BatchConverter.cancellableRecords(for:) throws`. It passes `Task.isCancelled` to the planner and checks for cancellation on each item while reading sizes.
- `ConversionRunner` awaits the detached planning task through `withTaskCancellationHandler { await planning.result } onCancel: { planning.cancel() }`. A cancellation during planning ends up in the existing `CancellationError` branch, so the run finishes as cancelled.
- `SummaryBox`:
  - Shows "Preparando arquivos…" (en: "Preparing files…") while the runner is running and has no records yet.
  - Now checks `wasCancelled` before `hasResults`, so a run cancelled during planning reads "Cancelado." in orange instead of "Pronto para processar.".
- New tests: `plannerStopsWhenCancelled` and `cancellableRecordsThrowWhenCancelled`.
- **Requires human verification:** check in the UI that Cancel is responsive on a large list.
